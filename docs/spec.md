# 口パク音声化アプリ 仕様書（フェーズ1：検証版）

作成日: 2026-10-13　更新: 2026-10-17（ローカル優先の構成に変更。クラウド版は `cloud-v1` として履歴に残す）
実装担当: Claude Code
作業前に `my_ai_tools/data/error_db.md` を必ず読むこと。

---

## 1. 目的

口パク（声なし）をカメラで読み取り、定型フレーズを判定して音声で再生する。
最終利用者は、発声はできないが口は動かせる人（気管切開後のALS患者など）。
利用者は **手動の操作（キーやボタン）ができない**。実使用は、画面が映っている間は口元を常時監視し、口パクを検出したら認識する（ステップ3）。手動の認識画面は、家族・開発者が精度を確かめるためのテスト用。
実使用の PC は **Windows 11 Home、AMD Ryzen 3 110、メモリ 8GB、内蔵 GPU** の低スペック機で、視線入力ソフトと同居する。**ネットがなくても動く**こと、負荷が低いことが要件。

フェーズ1では **開発者の顔で「データ蓄積→学習→定型文の判定」が成立するか** を検証する。
成立したら、同じ仕組みのまま利用者のデータに置き換える（フェーズ2）。

## 2. フェーズ1の合格基準

| 項目 | 基準 |
|---|---|
| 上位3候補に正解が入る率 | 90%以上 |
| 1位が正解の率 | 70%以上（参考値） |
| 口パク終了から候補表示まで | 2秒以内 |
| 評価データ | 学習に使っていない **別の日** の録画 |

同じ日のデータで評価すると数字が良く出すぎるので、必ず日を分ける。

## 3. フェーズ1の範囲

やること
- ローカルプログラム（利用者の PC の中で動く。ネット不要）
- データ収集画面（フレーズ表示→録画→保存。フレーズでない動き＝負例の収集を含む）
- 学習（本人専用の分類モデル。開発者の Mac で行い、モデルだけを PC に渡す形も可）
- 認識画面（口パク→候補3つ→選択→音声再生。テスト用）
- 評価レポート（正解率、取り違えの一覧、棄却の評価）
- 日次バックアップ（Google ドライブの同期フォルダへ）
- 常時監視、夜間アラート、自動発話（ステップ3）

やらないこと（フェーズ2以降）
- 本人の声の合成（フェーズ1はブラウザ標準の読み上げで代用。音声ファイルがあればそれを再生する）
- 自由文の認識
- スマホ対応
- クラウドでの複数利用者の運用（`cloud-v1` に実装が残っている）

## 4. 全体構成

利用者の PC の中だけで完結する（ネットがなくても動く）。サーバーは使わない。開発は Mac、実使用は Windows 11 で、同じコードで動かす。

```
[利用者の PC]
  ローカルプログラム（Python、常駐）
   ├ カメラ → MediaPipe Face Landmarker → 口の特徴点・口の開き
   ├ 録画（口が止まって1秒／最大10秒）→ 保存（~/LipVoice/<プロフィール>/）
   ├ 学習済みモデルで認識（numpy）                                  … 2b 以降
   └ ローカル API（127.0.0.1 のみ）→ 画面（ブラウザ。収集・設定・評価）
  日次バックアップ → Google ドライブ（デスクトップ版）の同期フォルダ  … 2c 以降
```

### 4.1 環境とデータの置き場所
- 開発（dev）は開発者の Mac、実使用（prod）は利用者の PC。**データは混ぜない**（プロフィールごとにフォルダを分ける。既定は `~/LipVoice/default/`。`--profile` で切り替える）
- フォルダの中: `config.json`（設定）、`lipvoice.db`（SQLite。フレーズ・クリップの記録）、`clips/<撮影日>/<id>.npz|.webm`、`models/`、`logs/`、`tmp/`、`orphans/`
- 顔検出のモデルは `~/LipVoice/assets/` に、初回だけネットで取得する（`lipvoice fetch-models`）。以後はオフラインで動く
- 制限値（フレーズ数、1日のクリップ数など）はハードコードせず、`config.json` に置く（既定は緩い）
- 学習は PyTorch（任意の依存）。推論は numpy のみ。学習は開発者の Mac で行い、できたモデル（小さなファイル）を PC に渡してもよい

### 4.2 ログイン
- ローカルプログラムにログインはない（利用者は 1 台の PC の 1 人）

### 4.3 アクセスの制限
- ローカル API は **127.0.0.1 のみ**で待ち受ける
- Host ヘッダの許可リスト（DNS rebinding の防止）、Origin の検査（`null` は拒否。他のサイトからの要求の防止）、起動ごとに作るトークン（画面に埋め込む。他のサイトは画面の中身を読めない）で守る
- 同じ PC の同じ利用者権限の他のプログラムは、ファイルを直接読めるので対象外（脅威モデル外）
- 顔由来のデータの保護は、OS のディスク暗号化に任せる（アプリ内の暗号化はしない。鍵をなくすと復旧できなくなるため）
- アプリ内に他人のデータを見る機能は作らない。開発者が利用者のデータを確認したい時は、バックアップのフォルダを Mac に持ってきて、`--home` を指定して開く（本人の同意のもと）

## 5. 技術選定

| 部分 | 採用 | 理由 |
|---|---|---|
| 画面 | React + Vite + TypeScript | カメラは扱わない。ローカルプログラムの状態を表示・操作するだけ |
| ローカルプログラム | Python + FastAPI + uvicorn | 127.0.0.1 のみ。画面（ビルド済みの React）も配信する |
| 映像取得 | OpenCV（Windows: Media Foundation、Mac: AVFoundation） | OS ごとの違いは薄い層に隠す。試験用に動画ファイルも使える |
| 顔の検出 | MediaPipe Face Landmarker（Python、CPU） | 口の特徴点と表情係数が取れる。収集も認識も同じパイプライン（ブラウザ版との数値のずれを避けるため） |
| 保存 | ファイル（npz・webm）＋ SQLite（WAL） | ネット不要。書き込み順序と起動時の検査で壊れにくくする |
| 学習 | PyTorch（任意） | 小さなモデルなら CPU で数分。重みは .npz（pickle なし）で保存 |
| 推論 | numpy | torch 不要。低スペックの PC でも軽い |
| バックアップ | Google ドライブ（デスクトップ版）の同期フォルダ | 無料枠の範囲。同期は Google ドライブ側が行う |

## 6. データ仕様

### 6.1 フレーズ一覧（SQLite `phrases`）
- フェーズ1は10個。画面から編集可能にする。個数と1つの長さの上限は `config.json`（既定は 1000 個、200 文字）。長い文も入れられる。
- 下は初期値（仮）。フェーズ2では利用者が普段の意思伝達装置で実際に使う定型文に差し替える。

```json
[
  {"id": "p01", "text": "痛い"},
  {"id": "p02", "text": "吸引して"},
  {"id": "p03", "text": "体の向きを変えて"},
  {"id": "p04", "text": "暑い"},
  {"id": "p05", "text": "寒い"},
  {"id": "p06", "text": "ありがとう"},
  {"id": "p07", "text": "テレビを消して"},
  {"id": "p08", "text": "口を湿らせて"},
  {"id": "p09", "text": "ちょっと来て"},
  {"id": "p10", "text": "大丈夫"}
]
```

### 6.2 1回の録画で保存するもの
| 置き場所 | 内容 |
|---|---|
| `clips/<撮影日>/<id>.npz` | 口・目・眉・鼻・顔の輪郭の **約 110 点の生の座標**（正規化前。x, y, z）、表情係数 52 個、口の開き、各フレームの時刻、検出できたか |
| `clips/<撮影日>/<id>.webm` | 口元の切り出し動画（96×96、グレースケール） |
| SQLite `clips` | 種類（フレーズ／負例）、phrase_id または負例の種類、由来（収集／実使用）、撮影日、セッション ID、録画の長さ、フレーム数、フレームレート、顔の検出率、終了の理由（`still` / `max` / `no_motion`）、ファイルの場所 |

- 特徴点の時系列は録画の長さに応じた **可変長** のまま保存する。64 フレームに揃える処理と、正規化（6.3）、動き区間の切り出しは、学習・認識の前処理 `ml/features.py` の 1 か所で行う（収集と認識で同じ関数を使う）。正規化前の座標を残すので、方式を変えても撮り直しは要らない
- 顔全体の 478 点は保存しない。保存先のパスは、`<撮影日>/<id>`（id はプログラムが採番）から常に組み立てる
- 動画は今回のモデルでは使わない。将来、より強い動画モデルに替える時に撮り直さずに済むよう、最初から残す。
- 顔全体の映像は PC の外に出さない。保存するのは口元の切り出しと特徴点だけ。カメラ位置の確認用に縮小映像をこの PC の画面にだけ表示できるが、保存しない。
- 保存は、一時ファイルに書く → fsync → 名前変更 → SQLite に記録、の順。途中で電源が落ちても孤児ファイルが残るだけで、起動時の検査（`lipvoice check`）で `orphans/` に退避する
- 1 クリップは約 200KB（特徴点 約 150〜190KB、動画 約 60〜100KB の実測）。250 本で約 50MB

### 6.3 特徴点の正規化
- 口角の中点を原点にする
- 両目尻の間隔で大きさを揃える
- 両目尻を結ぶ線で傾きを補正する

顔の位置・距離・傾きが変わっても同じ値になるようにするため。正規化は保存時ではなく、学習・認識の前処理（`ml/features.py`）で、保存した生の座標から行う。

## 7. 画面仕様

### 7.0 ログイン画面
- ない（4.2）

### 7.1 データ収集画面 `/collect`
1. フレーズを大きく表示
2. スペースキーを押して離した瞬間に録画開始（カウントダウンはしない）。声は出さずに口パクする
3. 次のどちらか早い方で録画が自動で終わる
   - 口の動きが止まって 1.0 秒経った
   - 止まらなくても、開始から 10 秒経った
4. 「保存」「撮り直し」を選ぶ
5. 次のフレーズへ（順番はランダム）

- 録画中は、残り秒数と「話し終えたら口を閉じてください」を画面に表示する
- キー操作: スペース＝離した時に録画開始、Enter＝保存して次へ、Backspace＝撮り直し
- キーはブラウザが前面の時だけ有効
- 画面に「今日の録画数」「フレーズごとの累計」を表示
- 1セッションは最大5分で自動終了（フェーズ2での本人の疲労対策）

**口が止まった判定**
- 口の開き ＝ 上唇と下唇（内側の中央）の距離 ÷ 両目尻の距離。顔の位置・距離が変わっても同じ尺度になる
- 直近 1.0 秒間の口の開きの変動幅（最大 − 最小）が閾値以下なら「止まっている」とみなす
- 一度動き出すまでは判定しない（録画開始直後の静止で終わらないようにするため）
- 動きが一度も検出されないまま 10 秒経った場合は「動きなし」とし、保存できない（撮り直し）
- 顔が十分に検出できなかった録画（検出フレームが 7 割未満）も保存できない
- 閾値は設定で変えられる（認識画面 7.2 と共通の設定）。初期値は 0.01（目尻間の距離の 1%）。あわせて「止まってから終了するまでの秒数」（初期値 1.0 秒、範囲 0.5〜3）と「最大の録画時間」（初期値 10 秒、範囲 3〜15）も変えられる
- 設定はフェーズ1では `/collect` 画面の折りたたみ欄（いまの口の動きの値を見ながら調整できる）に置き、ブラウザに保存する。`/settings`（7.4）ができたらそちらへ移す

### 7.2 認識画面 `/speak`
1. （テスト用の手動操作）「話す」ボタン、またはスペースキーを離した瞬間。利用者は手動の操作ができないので、実使用は常時監視（ステップ3: 口の動きを検出したら自動で録画）。手動はテスト用
2. 録画は 7.1 と同じ条件で自動的に終わる: 口の動きが止まって 1.0 秒経つか、開始から 10 秒経つか、早い方（録画中は残り秒数と「話し終えたら口を閉じてください」を表示する）
3. 候補3つを大きなボタンで表示 ＋「どれも違う」
4. 選ぶと音声再生
5. 選んだ結果を正解ラベルとして保存（次回の学習に使う）

- **録画の長さの条件は収集（7.1）と認識で必ず同じにする。** 利用者は長い文も口パクするため、条件が違うと学習データと実使用の入力の長さ・切れ目がずれ、精度が落ちる。「口が止まった」の判定の実装、閾値、静止秒数（1.0 秒）、最大秒数（10 秒）は両画面で共有し、片方だけ変えない（設定も共通）
- 認識画面でも、動きが一度も検出されないまま最大秒数に達した場合は候補を出さず、「口の動きが検出できませんでした」と表示してやり直しにする
- 候補ボタンは視線で押せる大きさ（1個あたり画面の横1/3 × 縦1/3 以上）
- 1位の確信度が 0.9 以上なら自動再生するモード（設定で ON/OFF、初期値 OFF）
- 「どれも違う」の時は、キーボードで正解フレーズを選べる
- 自分のモデルが未学習の場合は「まずデータ収集へ」と案内する
- 常時監視（ステップ3）では、画面は出さずに自動発話するのが目標。最初のテスト段階だけ候補を出して選び、選んだらすぐ待機画面に戻す。自動発話の条件は 14章

### 7.3 評価画面 `/report`
- 正解率（1位、上位3）
- 取り違え表（どのフレーズをどれと間違えたか）
- 日ごとの正解率の推移
- 「学習を実行」ボタン（自分のデータで再学習。完了まで数分）

### 7.4 設定画面 `/settings`
- フレーズの追加・編集・並び替え
- 自動再生モードの ON/OFF

## 8. 学習仕様

### 8.1 モデル（2段階で試す）
| 段階 | 方式 | 目的 |
|---|---|---|
| A | 時系列の距離で比べる方式（DTW + 近傍法） | 学習不要の基準値。まず動くか確認 |
| B | 小型の時系列モデル（1D-CNN または GRU） | 本命。フレーズごとの確率を出す |

Bで基準に届かない場合のみ、6.2 の動画を使う方式（学習済みの読唇モデルを土台にする）を検討する。これは別途相談。

### 8.2 入力
- 口の特徴点（40点 × x, y）＋ 表情係数のうち口・あご関連（`jaw*` と `mouth*` の 27 個。名前で選ぶ）
- 前処理（`ml/features.py`）: 保存した生の座標を正規化（6.3）し、口が動いている区間だけを前後 0.2 秒の余白つきで切り出し、時刻ベースで 64 フレームに揃える。切り出すことで、録画の始め方（収集はスペースを離して開始、認識は動きの検出で開始）が違っても、同じ形の入力になる
- 録画の長さ（秒）を特徴に加えるかは切り替え式。初期値は OFF（ALS では疲労で速さが変わりやすいため。実データで ON/OFF を別の日で比べて決める）

### 8.3 データの水増し
- 速度を0.8〜1.2倍に伸縮
- 特徴点に小さなノイズを加える
- 開始位置を前後にずらす

### 8.4 学習と評価の分け方
- 撮影日で分ける。既定は、最新の日を評価、それ以前を学習（例: 1日目・2日目で学習、3日目で評価）
- ランダムに分けない（同じ日のデータが両方に入ると過大評価になる）
- 日付が 1 日分しかない時は評価しない（学習はできる）。`--eval-dates` と `--train-dates` で指定でき、重なる指定は拒否する
- 日ごとの leave-one-day-out 交差検証で、件数（n/N）と分散を出す。標準化の値と棄却の閾値は学習側の日だけで計算する。最終モデルは全日で学習し直す
- 既定の学習データは `source=collect` のみ。実使用（`use`）は評価に使い、学習に入れるのは明示した時だけ（選択ミスでラベルが汚れるため）

### 8.5 学習とモデルの保存
- 学習は PC 内（または開発者の Mac）で、`lipvoice` のコマンドから実行する。低優先度の別プロセスで動かし、学習中も認識は旧モデルを使い続ける
- 学習済みモデルは `models/<日時>/`（`meta.json`、`dtw.npz`、`cnn.npz`、評価結果、使ったクリップの ID 一覧）に保存し、`models/active.json` が現在の版を指す。ロールバックは `active.json` の書き換えだけ
- 重みは .npz（pickle なし）。推論は numpy のみ
- 棄却: DTW は最近傍の距離の絶対値、CNN は各フレーズの代表との距離で、フレーズ以外の動き（あくび、咳、飲み込みなど）を弾く。閾値は交差検証で、負例の誤受理率が目標以下になる値を選ぶ
- Cloud Run Jobs での学習は、クラウド版（`cloud-v1`）にあった方式で、本線では使わない

## 9. 収集計画（開発者による検証）

| 日 | 内容 | 量 |
|---|---|---|
| 1日目 | 10フレーズ × 10回 | 100本 |
| 2日目 | 10フレーズ × 10回（照明・姿勢を変える） | 100本 |
| 3日目 | 10フレーズ × 5回（評価用） | 50本 |

撮影条件
- 声を出さない
- 口の動きは小さめも混ぜる
- カメラ位置は利用者の実環境に近づける（斜め上から寝ている姿勢を見る角度。実機で確認）
- 顔検出器の守備範囲は、正面から約 45° 以内（公式のモデルカード）。カメラの角度・上下の向きは、導入時に `lipvoice bench` で確認する（上下逆なら `camera_rotate` を 180 に）
- 解像度は 640×480 に統一する（収集も認識も）

試験（開発者の顔で、まとめて収集して流れを確かめる）
- 収集画面の「設定 → 試験用」で、撮影日の上書き（day1・day2・day3）と自動保存を使うと、1 日でまとめて集めても「3 日分」として記録できる。学習と評価は撮影日で分けるため（8.4）。実際の収集では、必ず空・オフに戻す
- 患者さん本人の収集は、疲労に配慮し、1 セッション 5 分（15〜20 本）、1 日に数セッション・休憩つきで、別々の日が 3 日以上になるように進める（3 日に固定しない）

負例の収集
- フレーズでない動き（あくび、咳、口を湿らせる、飲み込み、自由な口パクなど）を、収集画面の負例モードで録る。棄却の閾値の調整と、誤受理率の測定に使う
- 夜間（暗い環境）で使う場合は、実際の暗さの条件の録画を 1 日分加える（夜間アラート）

## 10. API（ローカル。すべてトークン必須）

127.0.0.1 のみ。Host/Origin/トークンの検査（4.3）。失敗は 403。画面から変えられる設定は録画の終了条件・試験用の項目などに限り、カメラ（`camera_*`）などは設定ファイルからだけ。

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/api/health` | カメラ・処理時間・顔の傾きの状態 |
| GET/PUT | `/api/settings` | 設定（録画の終了条件、試験用の撮影日の上書き・自動保存など） |
| GET/PUT | `/api/phrases` | フレーズ一覧・更新 |
| GET | `/api/stats` | 収集の件数 |
| GET | `/api/events` | 状態・口元プレビューのリアルタイム配信（SSE） |
| GET | `/api/collect/state` | 収集の状態 |
| POST | `/api/collect/mode` | フレーズ／負例の切り替え |
| POST | `/api/collect/start` | 録画の開始（口が止まる／最大秒数で自動終了） |
| POST | `/api/collect/save` `discard` `cancel` `skip` `undo` `session` | 保存・撮り直し・録画の中止・フレーズのスキップ・直前の保存の取り消し・新しいセッション |
| GET | `/api/collect/pending/video` | 確認中の口元動画 |
| POST | `/api/preview` | カメラ位置の確認用の縮小映像（この PC の画面だけ） |
| POST | `/api/speak/start` | 認識（テスト用）の録画の開始。終了すると候補 3 つと確信度、棄却の判定が出る |
| POST | `/api/speak/choose` | 選ばれた正解の保存。選んだ時だけ録画（特徴点と口元動画）を `source=use` で保存し、予測の記録も残す。「どれも違う」はキーボードで正しいフレーズを選ぶ。フレーズではない動きは負例（誤検知）として保存 |
| POST | `/api/speak/skip` | 保存せずにやり直す |
| GET | `/api/report` | 学習・評価の結果（`lipvoice train` が書く）と、実使用の日ごとの正解率、モデルの版 |
| POST | `/api/models/activate` | 使うモデルの版を切り替える（ロールバック） |

学習・評価はコマンド（`lipvoice train`、`lipvoice models`）で行う。画面からの実行は、のちのステップ。

## 12. コード規約
- 1ファイル300行以内を目標、500行超は必ず分割
- 1コンポーネント1ファイル
- 型定義は `web/src/types/` に集約
- 制限値はハードコードせず `config.json` に置く（既定は緩く）
- エラーは内容・原因・解決策を `error_db.md` に追記

## 13. フェーズ2（利用者本人への置き換え）で変わる点

| 項目 | フェーズ1 | フェーズ2 |
|---|---|---|
| 話者 | 開発者（自分のデータ） | 利用者（利用者の PC のプロフィール） |
| 動かす場所 | 開発者の Mac | 利用者の意思伝達装置 PC（Windows 11、低スペック） |
| 声 | ブラウザ標準の読み上げ | 本人の声（フレーズごとの音声ファイルを事前に作って再生。CoeFont の無償プラン、ElevenLabs の Impact Program などを検討） |
| 操作 | キーボード | 常時監視（手動の操作は不要）。収集は家族がキーボードで補助 |
| フレーズ | 仮の10個 | 利用者が実際に使う定型文 |

引き継げるもの: 画面、保存形式、学習・評価の仕組み、アプリそのもの。
引き継げないもの: 学習済みモデルと正解率。利用者のデータは利用者の PC で一から集める。

## 14. 安全上の決めごと
- 緊急の呼び出しはこの仕組みに頼らない。既存の手段を残す
- 既存の意思伝達装置は置き換えず併用する
- 自動再生（自動発話）は、取り違えが少ないと確認できるまで OFF。ON にする時は、フレーズごとの許可と閾値を設ける（初期値は全フレーズ「候補のみ」）。判断材料として、評価画面に「確信度の閾値ごとの自動発話率と、その中の誤発話率」を出す
- このアプリだけに頼り切らない。夜間アラートも含め、「検出できない」状態（暗すぎる、顔が見えない、処理落ち、カメラ切断）は必ず家族に分かる形で通知する。見逃しはゼロにできないので、既存のナースコールを併用する
- 口の動きは変化するため、フェーズ2では月1回の精度確認と再学習を行う
- 顔の映像・特徴点・音声は本人の PC とバックアップ（本人の Google アカウント）にだけ置く。バックアップは日次で、復元は 1 コマンドで行え、件数の一致を検証する（2c）
- 顔由来のデータの保護は OS のディスク暗号化に任せる（Windows 11 Home は「デバイスの暗号化」が使えるか実機で確認）
