# 口パク音声化ウェブアプリ 仕様書（フェーズ1：検証版）

作成日: 2026-10-13　更新: 2026-10-14（ログイン・アカウント分離を追加）
実装担当: Claude Code
作業前に `my_ai_tools/data/error_db.md` を必ず読むこと。

---

## 1. 目的

口パク（声なし）をカメラで読み取り、定型フレーズを判定して音声で再生する。
最終利用者は、発声はできないが口は動かせる人（気管切開後のALS患者など）。

フェーズ1では **開発者の顔で「データ蓄積→学習→定型文の判定」が成立するか** を検証する。
成立したら、同じ仕組みのまま利用者のデータに置き換える（フェーズ2）。

## 2. フェーズ1の合格基準

| 項目 | 基準 |
|---|---|
| 上位3候補に正解が入る率 | 90%以上 |
| 1位が正解の率 | 70%以上（参考値） |
| 口パク終了から候補表示まで | 2秒以内 |
| 評価データ | 学習に使っていない **別の日** の録画 |

同じ日のデータで評価すると数字が良く出すぎるので、必ず日を分ける。

## 3. フェーズ1の範囲

やること
- Googleログイン（利用者ごとにデータ・モデル・フレーズを完全分離）
- データ収集画面（フレーズ表示→録画→保存）
- 学習ジョブ（本人専用の分類モデル）
- 認識画面（口パク→候補3つ→選択→音声再生）
- 評価レポート（正解率、取り違えの一覧）

やらないこと（フェーズ2以降）
- 本人の声の合成（フェーズ1はブラウザ標準の読み上げで代用）
- 自由文の認識
- スマホ対応
- 家族を招待・共有する機能（4.3 参照）

## 4. 全体構成

最初からウェブ上で動かす。開発者も利用者も同じURLに自分のGoogleアカウントでログインし、
自分のデータだけを見る。開発者のテストデータが利用者のデータに混ざることはない。

```
[ブラウザ]                              [Cloud Run (Python/FastAPI)]
 Googleログイン（Firebase Auth）
 カメラ映像                                トークンを検証し uid を取り出す
  └ MediaPipe Face Landmarker              POST /clips    → GCS: users/{uid}/clips/
     ├ 口の特徴点の時系列 ───────────────→ POST /predict  → models/{uid}/ の専用モデルで判定
     └ 口元の切り出し動画 ────────────────→ GET  /phrases  → Firestore: users/{uid}/phrases
 候補ボタン3つ + 「どれも違う」             POST /feedback → Firestore: users/{uid}/feedback
 音声再生                                  POST /train    → 学習ジョブ起動（Cloud Run Jobs）
                                           GET  /report   → BigQuery から集計
```

### 4.1 アカウントの置き場所（2環境）

| 環境 | アカウント | GCPプロジェクト | 用途 |
|---|---|---|---|
| dev | 開発者のGoogleアカウント | 新規 `lip-voice-dev`（他の用途と同居させない） | フェーズ1の検証 |
| prod | 利用者本人のGoogleアカウント | 新規（事前に本人の了承を取る） | フェーズ2以降の本番 |

- コードは両環境で同一。差分は環境変数（`.env.dev` / `.env.prod`）と `.firebaserc` のターゲットだけ
- プロジェクトID、バケット名、Firebase 接続情報、API の URL は **コードに直書き禁止**。すべて環境変数から読む
- dev のデータ（開発者の録画・モデル）は prod に移さない。prod は空から始める
- prod では開発者を IAM で編集者として追加し、開発・運用を行う
- 両環境とも予算アラートを月1,000円で設定する
- 配置は `firebase deploy --only hosting` と `gcloud run deploy` をスクリプト化し、環境名を引数で切り替える（`scripts/deploy.sh dev|prod`）

### 4.2 ログイン
- Googleログインのみ（新規登録画面は作らない）
- 初回ログイン時に `users/{uid}` を作成し、初期フレーズ一覧をコピーする
- ログアウト状態では全画面をログイン画面にリダイレクトする
- 意思伝達装置のPCでは、利用者のアカウントでログインしたまま維持する（セッション有効期限は最長に設定）

### 4.3 データの分離
- すべてのデータは `uid`（ログインした人の識別子）の下にだけ置く
- Firestore / GCS のセキュリティルールで「自分の uid 以外は読めない・書けない」を強制する
- サーバー側も、リクエストのトークンから取った uid 以外には絶対に触らない
- 家族が利用者の画面を代理で操作する時は、利用者のアカウントでログインした端末（意思伝達装置のPC）を使う
- 開発者が利用者のデータを確認したい時は、GCPコンソール（編集者権限）から見る。アプリ内に他人のデータを見る機能は作らない

## 5. 技術選定

| 部分 | 採用 | 理由 |
|---|---|---|
| 画面 | React + Vite + TypeScript | ブラウザのみで動作 |
| ログイン | Firebase Authentication（Googleログイン） | 新規登録不要。Googleアカウントがあれば使える |
| 画面の配置 | Firebase Hosting | 無料枠内 |
| 顔の検出 | MediaPipe Face Landmarker（tasks-vision） | ブラウザ内で動く。口の特徴点と表情係数が取れる |
| サーバー | Python + FastAPI on Cloud Run（最小インスタンス0） | 使った時だけ課金。無料枠内の見込み |
| 学習 | PyTorch、Cloud Run Jobs で実行 | 小さいモデルならCPUで数分。月数回なら数十円〜数百円 |
| 録画・モデル | Cloud Storage | 無料枠 5GB |
| フレーズ・正解ラベル・設定 | Firestore | 無料枠内。ルールで uid 分離 |
| 集計 | BigQuery（manifest を日次で取り込み） | 評価画面の集計用 |

## 6. データ仕様

### 6.1 フレーズ一覧 `users/{uid}/phrases`（Firestore）
- フェーズ1は10個。画面から編集可能にする。
- 下は初期値（仮）。フェーズ2では利用者が普段の意思伝達装置で実際に使う定型文に差し替える。

```json
[
  {"id": "p01", "text": "痛い"},
  {"id": "p02", "text": "吸引して"},
  {"id": "p03", "text": "体の向きを変えて"},
  {"id": "p04", "text": "暑い"},
  {"id": "p05", "text": "寒い"},
  {"id": "p06", "text": "ありがとう"},
  {"id": "p07", "text": "テレビを消して"},
  {"id": "p08", "text": "口を湿らせて"},
  {"id": "p09", "text": "ちょっと来て"},
  {"id": "p10", "text": "大丈夫"}
]
```

### 6.2 1回の録画で保存するもの
| 置き場所 | 内容 |
|---|---|
| GCS `users/{uid}/clips/{clip_id}.json` | フレームごとの口の特徴点（x, y, z）と表情係数52個、時刻 |
| GCS `users/{uid}/clips/{clip_id}.webm` | 口元の切り出し動画（96×96、グレースケール、30fps） |
| Firestore `users/{uid}/clips/{clip_id}` | phrase_id, 撮影日, セッションID, 由来（収集／実使用）, 保存先パス |

- 特徴点の時系列は録画の長さに応じた **可変長** のまま保存する（口が止まって終了した場合の最後の約 1 秒の静止区間を含む）。64 フレームに揃える処理は学習側で行う（8.2）。Firestore には録画の長さ（`duration_ms`）と終了の理由（`stop_reason`: `still` / `max` / `no_motion`）も記録する
- 動画は今回のモデルでは使わない。将来、より強い動画モデルに替える時に撮り直さずに済むよう、最初から残す。
- 顔全体の映像はブラウザの外に出さない。送るのは口元の切り出しと特徴点だけ。

### 6.3 特徴点の正規化
- 口の中心を原点にする
- 両目の間隔で大きさを揃える
- 両目を結ぶ線で傾きを補正する

顔の位置・距離・傾きが変わっても同じ値になるようにするため。

## 7. 画面仕様

### 7.0 ログイン画面 `/login`
- 「Googleでログイン」ボタンのみ
- ログイン後は `/speak` へ

### 7.1 データ収集画面 `/collect`
1. フレーズを大きく表示
2. スペースキーを押して離した瞬間に録画開始（カウントダウンはしない）。声は出さずに口パクする
3. 次のどちらか早い方で録画が自動で終わる
   - 口の動きが止まって 1.0 秒経った
   - 止まらなくても、開始から 10 秒経った
4. 「保存」「撮り直し」を選ぶ
5. 次のフレーズへ（順番はランダム）

- 録画中は、残り秒数と「話し終えたら口を閉じてください」を画面に表示する
- キー操作: スペース＝離した時に録画開始、Enter＝保存して次へ、Backspace＝撮り直し
- キーはブラウザが前面の時だけ有効
- 画面に「今日の録画数」「フレーズごとの累計」を表示
- 1セッションは最大5分で自動終了（フェーズ2での本人の疲労対策）

**口が止まった判定**
- 口の開き ＝ 上唇と下唇（内側の中央）の距離 ÷ 両目尻の距離。顔の位置・距離が変わっても同じ尺度になる
- 直近 1.0 秒間の口の開きの変動幅（最大 − 最小）が閾値以下なら「止まっている」とみなす
- 一度動き出すまでは判定しない（録画開始直後の静止で終わらないようにするため）
- 動きが一度も検出されないまま 10 秒経った場合は「動きなし」とし、保存できない（撮り直し）
- 顔が十分に検出できなかった録画（検出フレームが 7 割未満）も保存できない
- 閾値は設定で変えられる（認識画面 7.2 と共通の設定）。初期値は 0.01（目尻間の距離の 1%）。あわせて「止まってから終了するまでの秒数」（初期値 1.0 秒、範囲 0.5〜3）と「最大の録画時間」（初期値 10 秒、範囲 3〜15）も変えられる
- 設定はフェーズ1では `/collect` 画面の折りたたみ欄（いまの口の動きの値を見ながら調整できる）に置き、ブラウザに保存する。`/settings`（7.4）ができたらそちらへ移す

### 7.2 認識画面 `/speak`
1. 「話す」ボタン（画面下の大きなボタン、またはスペースキー）
2. 録画は 7.1 と同じ条件で自動的に終わる: 口の動きが止まって 1.0 秒経つか、開始から 10 秒経つか、早い方（録画中は残り秒数と「話し終えたら口を閉じてください」を表示する）
3. 候補3つを大きなボタンで表示 ＋「どれも違う」
4. 選ぶと音声再生
5. 選んだ結果を正解ラベルとして保存（次回の学習に使う）

- **録画の長さの条件は収集（7.1）と認識で必ず同じにする。** 利用者は長い文も口パクするため、条件が違うと学習データと実使用の入力の長さ・切れ目がずれ、精度が落ちる。「口が止まった」の判定の実装、閾値、静止秒数（1.0 秒）、最大秒数（10 秒）は両画面で共有し、片方だけ変えない（設定も共通）
- 認識画面でも、動きが一度も検出されないまま最大秒数に達した場合は候補を出さず、「口の動きが検出できませんでした」と表示してやり直しにする
- 候補ボタンは視線で押せる大きさ（1個あたり画面の横1/3 × 縦1/3 以上）
- 1位の確信度が 0.9 以上なら自動再生するモード（設定で ON/OFF、初期値 OFF）
- 「どれも違う」の時は、キーボードで正解フレーズを選べる
- 自分のモデルが未学習の場合は「まずデータ収集へ」と案内する

### 7.3 評価画面 `/report`
- 正解率（1位、上位3）
- 取り違え表（どのフレーズをどれと間違えたか）
- 日ごとの正解率の推移
- 「学習を実行」ボタン（自分のデータで再学習。完了まで数分）

### 7.4 設定画面 `/settings`
- フレーズの追加・編集・並び替え
- 自動再生モードの ON/OFF
- ログアウト

## 8. 学習仕様

### 8.1 モデル（2段階で試す）
| 段階 | 方式 | 目的 |
|---|---|---|
| A | 時系列の距離で比べる方式（DTW + 近傍法） | 学習不要の基準値。まず動くか確認 |
| B | 小型の時系列モデル（1D-CNN または GRU） | 本命。フレーズごとの確率を出す |

Bで基準に届かない場合のみ、6.2 の動画を使う方式（学習済みの読唇モデルを土台にする）を検討する。これは別途相談。

### 8.2 入力
- 口の特徴点（約40点 × x, y）＋ 表情係数のうち口・あご関連
- 長さは64フレームに揃える（保存済みの特徴点は可変長。この整形は学習・推論の前処理 `ml/features.py` で行う）

### 8.3 データの水増し
- 速度を0.8〜1.2倍に伸縮
- 特徴点に小さなノイズを加える
- 開始位置を前後にずらす

### 8.4 学習と評価の分け方
- 学習: 1日目・2日目
- 評価: 3日目
- ランダムに分けない（同じ日のデータが両方に入ると過大評価になる）

### 8.5 学習ジョブ
- `/train` を呼ぶと、その uid のデータだけで Cloud Run Jobs を起動する
- 学習済みモデルは GCS `models/{uid}/latest.pt` に保存。旧版は日付付きで残す
- 学習中は画面に進行状況を表示し、完了後に自動で `/predict` が新モデルを使う

## 9. 収集計画（開発者による検証）

| 日 | 内容 | 量 |
|---|---|---|
| 1日目 | 10フレーズ × 10回 | 100本 |
| 2日目 | 10フレーズ × 10回（照明・姿勢を変える） | 100本 |
| 3日目 | 10フレーズ × 5回（評価用） | 50本 |

撮影条件
- 声を出さない
- 口の動きは小さめも混ぜる
- カメラ位置は利用者の実環境に近づける（正面、やや見上げる角度）

## 10. API（すべて認証必須）

| メソッド | パス | 内容 |
|---|---|---|
| GET | `/phrases` | 自分のフレーズ一覧 |
| PUT | `/phrases` | フレーズ一覧の更新 |
| POST | `/clips` | 録画データの保存 |
| POST | `/predict` | 特徴点の時系列を受け取り、上位3候補と確信度を返す |
| POST | `/feedback` | 認識画面で選ばれた正解を保存 |
| POST | `/train` | 自分のモデルを再学習 |
| GET | `/train/status` | 学習の進行状況 |
| GET | `/report` | 評価結果 |

- 全エンドポイントで Firebase の IDトークンを検証する。未認証は 401
- uid はトークンから取る。リクエスト本文の uid は信用しない

## 13. フェーズ2（利用者本人への置き換え）で変わる点

| 項目 | フェーズ1 | フェーズ2 |
|---|---|---|
| 話者 | 開発者（自分のアカウント） | 利用者（自分のアカウント） |
| 動かす場所 | 開発者のPC | 利用者の意思伝達装置PC（テレビ表示） |
| 声 | ブラウザ標準の読み上げ | 本人の声（ElevenLabs と CoeFont を比べて近い方） |
| 操作 | キーボード | 視線で選択。収集時は家族がワイヤレスのキーボード・マウスで補助 |
| フレーズ | 仮の10個 | 利用者が実際に使う定型文 |

引き継げるもの: 画面、保存形式、学習・評価の仕組み、アプリそのもの（同じURL）。
引き継げないもの: 学習済みモデルと正解率。利用者のデータは利用者のアカウントで一から集める。

## 14. 安全上の決めごと
- 緊急の呼び出しはこの仕組みに頼らない。既存の手段を残す
- 既存の意思伝達装置は置き換えず併用する
- 自動再生モードは、取り違えが少ないと確認できるまで OFF
- 口の動きは変化するため、フェーズ2では月1回の精度確認と再学習を行う
- 顔の映像・特徴点・音声は本人のアカウントの下にだけ置き、他の利用者からは見えない
